订阅是工单与线程之间的关系。接单会订阅它的每个触发所在的线程；绑定工单的 PR 会订阅该 PR 线程。

此后，订阅线程上的每条消息——无论来自谁或机器人——都会作为上下文送达订阅的工单；它不带授权，也不要求提及或通过发送者校验。

送到工单自己线程上的人的消息不再评估：由该工单的执行器判断是否属于本工单，不属于的交回，主 Session 会收到 follow_up 通知。其他消息仍要评估，只有策略允许时才成为候选：允许的发送者明确提及、该来源策略中的接单表允许，或该线程已有工单。

已结束的工单保留订阅，包括已关闭或已合并 PR 的工单：人在这里留言时，工单会在你看到之前按原授权恢复；机器人和 CI 不会唤醒它。

PR 被确认关闭或合并后，绑定的工单结束并保留对该 PR 的订阅，除非该工单还有自己开的未关闭 PR，或有已恢复但尚未报告就绪的工作。

被人叫停的工单保持结束，不再接收任何东西；要在这里开展新工作，必须经 orchestrator_route 接单。

orchestrator_thread_unsubscribe 移除线程上的全部工单订阅；之后一次新的接单决定可以重新订阅。

触发处置记录过滤、评估和决定，以及送达的工单；orchestrator_trigger_requeue 把保留的触发重新排队，等待新的评估。

机器人和 CI 不能授权工作。

普通讨论不必回复，也不必改代码。
